# KathanaBot 1.0.107

## What changed

- **Fixed Hold on Place / Leveling Navigation interrupting active combat to reposition.** Movement corrections could previously fire in the very same tick as an attack, or right after one - and in most action-combat games, a movement key press cancels whatever attack/skill animation is playing. That's what was causing "attacks stop mid-fight to move a little": the correction wasn't the problem, it was landing on top of combat. Movement and attacks can no longer be sent in the same tick, and Hold on Place / Navigation Travel now wait at least 600ms after the last attack before correcting position, so repositioning happens between fights instead of during them.
- **Fixed a remaining case where the Monster Filter still attacked a blacklisted mob right after a retarget.** Every retarget key press (search, stuck-bypass, avoid-high-max-hp, Dadati evade) now immediately clears the cached/confirmed mob name from the previous target. Before this, a stale "confirmed allowed" name from the target you'd just left could still count as valid for a tick or two after the game had already switched to a new (possibly blacklisted) target - if the fresh OCR read hadn't landed yet, an attack could fire against that new target using the old target's identity. The bot now strictly follows retarget -> scan OCR -> decide: it will not attack or buff again until a fresh read of the current target's name comes back and clears the filter.
- **Added a "Match %" setting to the Monster Filter**, right next to Mode and Name Check, so it behaves like Loot Name Match %: an OCR-read mob name only needs to be this close (not byte-for-byte identical) to a listed name to count as a match. Helps when OCR occasionally misreads a letter or two in a mob's name. Uses the same fuzzy-matching scorer as loot names.
- **When Monster Filter is disabled, its other options now fully hide** instead of just graying out: Mode, Name Check, Match %, the listed-names box, and the add/remove row. They reappear as soon as the filter is switched back on.
- **Several advanced/tuning settings are now hidden behind Developer Mode**, to keep the everyday UI simpler: the Vision tab's Selected Process / Loop (ms) / Normal Retarget / Mob HP Presence % / Forced Retarget row, the Auto Pot tab's "Unstuck / Retarget" group, the Auto Loot tab's "Pickup By Name (Dynamic Label Click)" group, and the "Verify (ms)" field next to Loot Pickup's interval. They reappear automatically once Developer Mode is switched on, with all values and behavior unchanged.
- **Moved the Developer Mode toggle into the Combat Full tab**, below "Hold to Show Game Window" in the main control column (it was previously a separate bar above the tabs, which has been removed). The Diagnostics tab stays hidden until Developer Mode is switched on, and the setting is remembered between sessions.
- **Healing and mana potions now always fire, regardless of the monster filter or any other gate.** Support actions (heal/mana/max-health) used to be skipped on any tick where a forced retarget or another action (auto-accept, repair, evade, etc.) had already happened - meaning a low-HP moment could occasionally go unhealed while the bot was busy handling a blacklisted or otherwise blocked target. Heal/mana now always get first chance to fire every loop tick.
- **Fixed the Monster Filter still attacking blacklisted/non-whitelisted mobs in some cases.** The filter's "wait for OCR name confirmation" gate only applied while the target window was visible on-screen that same frame. When it wasn't (e.g. a stale combat lock, or the mob-HP-bar-color fallback used to finish off a target near death), the bot could keep attacking without ever re-checking the mob's name against the filter. Attacks now require a fresh, OCR-confirmed mob name match against the filter at all times, regardless of whether the target window happened to be visible that tick.
- **Buffs no longer cast on a filter-blocked mob.** Previously buff keys were only paused while in Blacklist mode; in Whitelist mode a non-listed mob could still get buffed. Buffs are now suppressed any time the monster filter blocks the current target (blacklist match, non-whitelisted, or name not yet OCR-confirmed), in either mode.
- **Added High / Medium / Low bot-speed buttons right next to the Attack (run) button** in the Combat Full tab, so you can change how often the bot re-checks for mobs and re-runs OCR/combat logic without leaving the main controls: High = every 200ms, Medium = every 500ms, Low = every 1000ms. Stays in sync with the existing "Loop (ms)" field in the Vision tab.
